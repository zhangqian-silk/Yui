# T11 技术方案｜按使用边界热插拔

硬依赖：T04、T09。

任务定义：[交付范围与证据](../tasks/T11-hot-reload.md)。

## 1. 更新边界

热插拔的目标是更新能力而不停止整个 Yui。三种实际边界：无状态展示随注册生效；短工具在当前调用结束后换实现；Endpoint 默认按 Session 更换。存储和核心授权契约不纳入任意热替换。

用户选择 reload 时，返回实际采用方式和仍在使用旧实例的引用，不承诺所有运行中对象即时变成新版本。

## 2. 新实例准备

获取并验证新产物，建立候选实例和完整贡献集合。必要依赖、schema、权限和环境检查通过后发布新的选择。初始化不做业务副作用，失败撤销候选 effects，原实现仍服务当前工作。

一次 Registry 切换只影响新的 acquire。没有新工作选择到半初始化 Provider。版本名与代码摘要绑定，不能更新同一目录却继续声称旧 generation 内容不变。

## 3. 短调用

call 在开始时 acquire Provider，到结果与必要回执保存后 release。新实现可以在旧调用进行时注册，后续独立调用使用新实现。当前调用即使发生 unknown，也不能为了 drain 直接再执行新实现。

当操作结果未知且后续查询需要原实现时，保留必要产物；已有结果完全固定后，不因为历史 operationRef 存在而永久保留代码。

## 4. 长期 Session

Session 取得 Endpoint 和实际持有的状态型依赖。新 Turn 在同一 Session 默认仍使用这组实现。新 Session 使用当前 Provider，配置与来源分别记录。

不要求通用 live handover。负责人可以等待、显式取消或在适当时机新建 Session。Session 结束后旧实例引用归零即可清理；空闲但仍明确续用的 Session 可以继续持有。

只固定有状态依赖，不把能力目录、所有 Project 和历史结果连成永久锁。动态新增短工具依然通过稳定桥在旧 Session 后续调用可见。

## 5. 停用与撤权

普通 disable 停止新的独立使用，让已取得句柄结束。明确撤销授权则影响后续受控副作用，即便旧句柄仍存在。两者在界面和 API 中分开表达。

停止请求不等于进程已停止，drain 超时只返回仍在使用的事实，不自动升级成杀死共享服务。需要强制处理时由 Operator／用户作明确选择，并记录可能未决的外部效果。

## 6. 历史与清理

产物保留依据是活跃使用、未决操作、明确的续用意图或用户保留。Candidate 和 Review 保存结果及来源信息，不要求可执行代码永久存在。

清理后历史页面仍能读取报告和原输出。再次要求按旧实现执行时可以返回能力需要安装，而不是把历史结果标成损坏。

## 7. 实施验证

用可阻塞的工具实例 A 启动一次调用，再启用 B。证明 A 返回原结果、B 处理新调用，A 完全释放后才 dispose。模拟 B 注册失败，A 仍可用。

再用长期 Session A 启动及结束一个 Turn，启用 B 后在同一 Session 发下一 Turn，确认仍由 A 处理；新建 Session 使用 B。测试在旧 Session 内通过稳定桥调用一个新短工具，证明两种更新边界相互独立。

最后停止旧会话并清理代码，验证历史 Candidate 可读。撤回 grant 后旧句柄不能继续发新的受控副作用。

## 8. 验收

S14／S35 验证 Session 边界；S25 验证短调用；S42 验证新能力可见；S37 验证结果与代码保留独立；S45 验证授权时效。

这些必须包含实际实例计数与请求记录，不以“状态显示 draining”作为真实停止或清理完成的证据。
