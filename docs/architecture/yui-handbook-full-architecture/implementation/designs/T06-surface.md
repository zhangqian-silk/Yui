# T06 技术方案｜统一 CLI 与 Web 入口

硬依赖：T03。

任务定义：[交付范围与证据](../tasks/T06-surface.md)。

## 1. 统一应用入口

定位 CLI 参数解析、Web 请求 handler、Agent 工具和 Task 查询投影。把同一语义的操作指向 T02 的能力或同一 typed handler；不要求所有内部调用强制经过 JSON。

Surface 只处理输入、确认、显示与订阅。Task 是否可接受、如何修复执行和是否重新评审不在前端判断。

## 2. 两个对话目标

定义 Global Operator 与 Task Leader 两种目标。Task 在 Draft 也可显示聊天入口；T08 提供实际 planning Session 时直接接入，T06 不自己伪造运行时。

全局配置操作走用户或 Operator 的身份；Task 对话使用 Leader 的 Task 身份。自然语言文本不决定 API 权限，认证来源来自实际入口。

## 3. 工作视图

Task 页先显示目标、当前要求、责任、结果、未答问题和明确进度。展开区域显示实际 Agent、Session、Turn 以及带观察时间的活动。

同时展示 Role 当前配置与运行中有效配置，避免用户误认为刚修改模型就已切换当前进程。历史输出使用其来源信息，不随当前配置重命名。

Context 的核心快照与 cursor 原样保留。可选观察和面板独立标注不可用，不把缺失数据填成正常。断线后按固定上界补读或重建快照。

## 4. 调用反馈

本地修改返回记录及 revision；外部请求返回 operationRef。界面区分未提交、排队、正在等待、明确结束和未知处置，不用“失败，立即重试”作为通用交互。

对破坏性或新授权操作采用清楚确认，其余已授权操作不重复加入人工流程。重复点击使用同一请求引用时不重复产生外部动作。

## 5. 命令与面板贡献

CLI 贡献描述命令名、帮助与 capability 映射；Web 贡献先使用受控数据面板、链接或已知渲染类型。注册与卸载绑定实例 disposer。

插件不能把任意脚本注入用户页面作为默认扩展方式。代码型 UI 如确有需求另按明确授权引入，不阻塞基本能力展示。

动态贡献应允许用户读到已保存结果，即使其专用面板已卸载。提供通用文本、文件和来源入口，而不是缺插件就整页报错。

## 6. 兼容与实施顺序

从查询和一个常用操作开始迁移，保留现有命令别名与可读输出。大量 CLI 目录拆分可以随真实 handler 接入进行，不必一次重写所有命令树。

Web 部分逐个使用统一 Context 和 handler，不能双写前端状态来保证临时兼容。浏览器本地状态仅用于视图选择，不拥有业务进度。

## 7. 验收

S15／S16 验证 Context 和消费分离；S30 验证歧义与可选能力；S36 验证配置显示；S38 验证贡献卸载；S46 验证局部面板失败不影响核心读取。

S19／S20 确认 Surface 只呈现角色上报和普通操作，没有新增 Operator 恢复机制。真实 Draft 对话在 T08 与本任务的视图结合验收。
