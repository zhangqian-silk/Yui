# T01 技术方案｜基础宿主与操作事实

硬依赖：T00。

任务定义：[交付范围与证据](../tasks/T01-kernel-host.md)。

## 1. 改动边界

定位现有存储事务、命令调用、Controller 实例管理、授权和外部请求记录。新增的是共用宿主与统一处置语义，不是替换所有 Store 或再建一个 Command 数据库。

## 2. 实例宿主

Host 保存一份进程内实例集合。每个实例有稳定实现引用、生命周期和 disposer 集合。接口可采用 attach／acquire／release／detach。acquire 返回具体句柄，使用方在 finally 或受控 Session 关闭时 release。

普通调用计入短期引用，Session 计入长期引用。配置 scope 只有 Global／Project／Task，不为了计数再创建 Role／Turn 插件 scope。

宿主只认识贡献与依赖句柄，不认识 Review 或 Task 计划。模块在装配入口注册到同一宿主。无引用时按拥有关系释放 listeners、timers、routes 和本地进程附件，不能杀共享 Provider 服务。

## 3. 操作事实

将现有副作用记录映射成请求身份、输入摘要、调用者、目标、所选实现、状态、效果和回执。若已有记录承担同一职责，扩展它，而不是同步双写两套表。

只读直接执行受权查询。本地修改用同一事务提交业务记录及必要来源。外部动作在发出前保存请求身份；记录 effect 为 none／possible／confirmed，outcome 另保存成功、失败或取消。

相同 requestId、目标和输入重复调用，返回原记录或继续查询原处置。相同 requestId 配不同输入，返回明确冲突。unknown 不触发自动调用其他实现。

## 4. 测试驱动的故障点

构造一个可控制的假外部服务，能够分别在发送前、接受后、效果发生后、回执返回前中断。测试端记录实际接收次数；Yui 端检查本地记录与真实次数对应。

重点证明：失败但已有效果仍保留回执；输出转换失败不能清零效果；正常 pending 不被自动重发；恢复后读到原操作而不是创建新操作。

本地修改用临时数据库模拟并发 revision 更新。冲突不覆盖对方字段，错误带当前版本；不把 revision 冲突扩展为结果有效性规则。

## 5. 可信调用上下文

用户 CLI、受控 Agent 工具和插件入口各自先认证，再构造调用上下文。插件输入中出现 actor=operator 不影响真实身份。Task／资源关系通过应用入口传入检查，Kernel 不内置所有业务角色策略。

凭据引用可在当前授权下解析，值不能进入日志和持久化输入摘要。撤销管理绑定后旧承载不能发新管理命令，但可信采集器仍可写它已有 Turn 的迟到结果。

## 6. 存储采用

新字段或操作索引通过当前支持的 migration 链增加。普通 Controller 启动不隐式猜测修复未知 schema。测试备份在隔离 Home，不能以可回退代码路径代替数据恢复验证。

若暂时只有一部分动作使用共用入口，保持旧入口为当前事实写入者，新的 adapter 调用它；不能同时写新旧两份处置。

## 7. 验收

S09／S34 验证未知与部分效果；S10 验证本地 CAS；S25 验证句柄切换；S45 验证撤权；S44 验证升级采用；S20 确认未新增任何 Operator 自动恢复机制。

完成后提供可供 T02 使用的宿主和操作端口，以及每项测试的实际结果。基础宿主不要求已经具备完整生产热重载，T11 再验证长期使用边界。
