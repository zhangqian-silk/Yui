# T09 技术方案｜插件开发工具与受权执行

硬依赖：T02、T05。

任务定义：[交付范围与证据](../tasks/T09-plugin-sdk.md)。

## 1. 最小开发面

提供 create、validate、activate、disable 四个入口。create 建立独立开发目录及 manifest／示例实现；Agent 可以使用已有文件和执行工具编写内容。构建产物、验证报告和源码是文件／记录，不需要 Source→Built→Staged 的长期业务状态机。

声明式模板直接由可信解释器处理。可执行插件使用明确授信的运行环境，不默认进入 Controller 进程。

## 2. Manifest 与产物

manifest 定义 id、版本、入口、能力、依赖、权限和 reloadMode。目录扫描阶段只解析数据，不 import 作者代码。能力描述必须可在执行作者初始化前校验名称、输入输出和所需权限。

验证实际代码／依赖产物并计算内容摘要。报告保存摘要、环境和执行了哪些测试。activate 重新检查内容是否一致及当前授权，不仅比较版本字符串。

构建命令和测试同样可能有副作用，使用与信任方式一致的环境。不能把安全检查建立在作者自己的 validate 函数先获得任意权限之上。

## 3. 运行方式

可信内建可以同进程；声明式由内建解释器执行；自动生成的代码优先在已配置的受限环境中运行，并通过受权工具访问资源。用户明确选择 trusted-local 时允许相应执行，但不声称具有未实现的隔离保证。

T05 提供环境选择与授权；T09 对实际使用的方式验证边界，不要求自建一个通用沙箱系统。如果只有声明式路径已经可用，应清楚交付该能力，可执行闭环仍需单独证据。

## 4. 初始化和注册

activate 先加载候选实例并建立完整贡献集合，在发布前检查依赖、名字冲突、契约和权限。初始化只能准备注册，不进行发送、发布或修改用户资料等业务动作。

发布是一项清楚的目录切换。失败释放候选 effects，不留下部分已注册命令。新实例不覆盖核心管理能力；Task scope 无权替换承载自身的 Runtime。

## 5. 调用安全

真实权限来自入口与资源 grant。插件参数不能指定更高 actor；嵌套能力调用保持同一身份。受控查询不能通过下游能力偷偷写入。

若插件直接运行在 trusted-local，文档要明确该边界不是强隔离。任务权限和 Scope 的逻辑检查仍有效，但无法据此承诺宿主文件绝对不可访问。

## 6. 验证集合

结构验证：manifest、入口、能力集合、schema 与 required dependencies。

生命周期验证：load、完整注册、调用、disable、effects 释放；初始化失败不破坏现有目录。

行为验证：合法输入、错误输入、部分效果后的输出校验失败；当前 grant 撤回后的下一次受控调用。

信任验证：开发、构建、测试和运行均不能超出其实际环境承诺。负向测试必须在所选真实隔离环境执行，不能以类型检查或 mock deny 替代。

## 7. 兼容与验收

现有内建插件可以先使用 trusted-builtin 路径，不强迫它们全部进入独立进程。外部 SDK 与稳定调用入口接入后，不需要修改 Yui 安装目录。

S28／S45 验证权限；S29 验证初始化；S31 验证报告与产物一致；S34 验证真实效果不被输出错误抹除。产物验证成功是加载条件，不是业务任务完成的条件。
