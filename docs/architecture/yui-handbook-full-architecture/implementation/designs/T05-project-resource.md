# T05 技术方案｜Project、Resource 与成果保存

硬依赖：T02。

任务定义：[交付范围与证据](../tasks/T05-project-resource.md)。

## 1. 通用入口

建立 Project 背景、Resource 引用、Environment 准备和 Artifact 保存的公开边界。Core 不要求 resource 是仓库，Task 不保存领域分类。

读取当前 Git、worktree、ChangeSet、检查和 Integration 实现，保留它们已有的资源保护，通过具体能力暴露。它们可以继续使用原表或原文件，由一个 adapter 读写，不能为了抽象同时维护新旧数据副本。

## 2. Project 与权限

Project 提供 knowledgeRefs、resourceRefs 和默认 Provider 配置。Task 引用 Project 只获得可见背景，不因此拥有全部外部凭据。动作入口按实际调用者检查资源授权。

资源定位信息与 credential 分开。保存 credential reference，运行时解析；产物、日志与配置快照不包含 secret 值。需要更大范围时由 Agent 请求授权，不由环境准备自动放宽。

## 3. Environment 接口

准备接口返回 preparationId、资源列表和可选 environmentRef。空环境有效。准备完成不等于被 Task 采用；采用在检查当前任务意图相关资源、配置与授权后记录一次明确归属。

暂时创建的目录或连接由 preparation 拥有，未采用时可清理；采用后由 Task／执行引用其使用事实。实际采用成功后启动 Agent 失败，不能把已创建资源伪装成从未发生。

不建立通用资源编排引擎。多项目准备失败时，保存已准备的引用并回收确定未采用部分；若某资源结果未知，返回证据让负责人处理，不对未知对象做破坏性清理。

## 4. Artifact

保存内容时计算摘要或创建不可变副本；外部结果记录具体版本及验证来源；动作结果关联回执。普通 URL 作为 ReferenceMaterial，不被标为固定版本。

Candidate 只引用稳定成果。临时工作区中仍会变化的文件，提交时要明确保存该版内容；后续原文件继续变化不改变已提交结果。Task direct 完成也可使用相同产物引用。

历史读取应使用内容存储或外部版本，而不是启动原生 Runtime。插件元数据用于来源展示，不产生永久代码保留需求。

## 5. 并行资源使用

具体资源插件识别必要的规范目标，避免两个别名被认为不同对象而冲突写入。Leader可以通过隔离工作环境并行，不必对所有资源建立复杂租约。

停止或换绑之后仍可能写入的资源不能被立刻复用为另一个冲突执行。对于可以建立新隔离环境的情况，允许继续推进其他工作。不要把“有一个资源未确认静止”变成全 Task 的阻塞状态。

## 6. 非软件验证

使用一个授权本地 JSON／文本材料 Task，不加载 Git 插件，创建结果文本或文件并保存 Candidate／完成说明。需要 Review 时把对应 Artifact 交给 Reviewer，不制造 branch 或 worktree。

这个场景验证通用 Core，而不是要求建设正式 Research Domain。可选工具和 Skill 继续以插件或配置组织。

## 7. 数据迁移与正常使用

先从公开接口去除 Git 必填假设，物理数据仍可沿原软件实现存储。必要 schema 变更遵守当前 Home 更新契约，读取旧结果不能要求其执行环境还存在。

每步都确认现有软件交付路径仍可用，尤其检查、目标更新和资源清理。接口通用化不应削弱实际 Git 动作的安全条件。

## 8. 验收

S04／S27 验证无 Git 和空环境；S13 验证固定成果；S26 验证资源身份；S22／S23 验证并行与停止；S28 验证 scope 与授权；S37 验证历史读取不依赖旧代码。
