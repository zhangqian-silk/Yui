# T05｜Project、Resource 与成果保存

硬依赖：T02。

## 交付目标

让任务使用通用项目背景、资源及产物，同时保持现有 Git 交付能力。

**完成状态：** 有 Git 和无 Git 的任务都能保存可读取成果；环境创建、采用与清理有明确所有权。

## 责任范围

- 明确 Project 知识、资源和默认能力配置。
- 提供环境 prepare／adopt 与空环境路径。
- 固定结果内容或外部版本，并让历史读取独立于 Runtime。

## 可独立分工的工作

1. 接入资源引用与授权。
2. 包装当前 Git／worktree／integration 能力。
3. 实现 Artifact 与无 Git 结果验证。

这些分工供 Leader 判断，不要求按步骤建立 WorkItem。紧密耦合的实现应由同一责任单元完成。

## 不在范围内

- 不创建领域分类框架或万能 Resource CRUD。
- 不要求一次性物理搬迁所有 Git 记录。

## 完成证据

- 无 Git Task 可直接完成并读取成果。
- 未采用环境能清理，用户资源不被误删。
- 历史结果读取不要求启动原插件。

验收场景：S04、S13、S22、S23、S26、S27、S28、S37。场景定义见[统一验收说明](../../reference/acceptance-scenarios.md)。
