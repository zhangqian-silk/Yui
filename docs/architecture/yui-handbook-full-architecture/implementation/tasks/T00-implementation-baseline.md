# T00｜实施基线与模块契约

硬依赖：无。

## 交付目标

确认当前实现中每项事实和副作用的唯一归属，建立可重复的正常使用基线，并将七模块边界映射到实际代码。

**完成状态：** 一份可执行的代码职责地图、主路径基线和接口采用顺序；不改变用户运行行为。

## 责任范围

- 识别 Task、Role、Turn、消息、资源和插件相关入口及真正的持久化位置。
- 标出当前 Codex／Claude 启动、投递、取消、恢复和结果归档路径。
- 列出必须继续工作的普通操作及可在隔离 Home 使用的验证材料。

## 可独立分工的工作

1. 梳理记录所有权与读写链。
2. 整理运行与资源生命周期。
3. 建立主路径验证入口及兼容约束。

这些分工供 Leader 判断，不要求按步骤建立 WorkItem。紧密耦合的实现应由同一责任单元完成。

## 不在范围内

- 不重写运行时、不改 Task 生命周期、不对用户正在使用的 Home 执行迁移。
- 不把本设计的每个类型机械映射成新表。

## 完成证据

- 职责地图中的每个关键记录有且只有一个权威写入入口。
- 主路径至少覆盖 Operator、Task、Leader 和一个现有软件交付过程。
- 真实账户和付费资源的测试边界单独说明。

验收场景：S39、S44。场景定义见[统一验收说明](../../reference/acceptance-scenarios.md)。
