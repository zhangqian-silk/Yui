# T02｜能力入口与内建实现接入

硬依赖：T01。

## 交付目标

建立简单而明确的能力目录，把当前实现放到稳定入口后面，使 Agent、CLI 和 Web 可以使用同一操作语义。

**完成状态：** search／describe／call 能发现并调用现有能力；实现替换不要求上层依赖具体类。

## 责任范围

- 定义名称、schema、效果和 Provider 描述。
- 将 Task、配置、执行、资源及插件管理入口包装为受权能力。
- 处理显式选择、同名歧义和 scope 可见性。

## 可独立分工的工作

1. 实现 Registry 与描述查询。
2. 接入一组当前真实内建能力。
3. 验证共享存储、权限与错误返回。

这些分工供 Leader 判断，不要求按步骤建立 WorkItem。紧密耦合的实现应由同一责任单元完成。

## 不在范围内

- 不强制每个模块成为独立 Service 或 RPC。
- 不同时改 Runtime 协议和 Task 数据语义。

## 完成证据

- 一个能力可被不同入口调用且只写一份事实。
- Task-local 实现不能遮蔽核心管理操作。
- 缺能力和歧义可读，不按加载顺序自动择一。

验收场景：S25、S30、S34、S39、S45。场景定义见[统一验收说明](../../reference/acceptance-scenarios.md)。
