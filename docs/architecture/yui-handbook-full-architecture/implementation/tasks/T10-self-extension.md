# T10｜原 Task 中的 Agent 自扩展

硬依赖：T03、T04、T09。

## 交付目标

让 Leader 面对缺少的能力，自己选择复用、组合或实现插件，并在原任务中真正使用。

**完成状态：** 实际业务任务通过新能力得到结果，而非仅演示插件加载。

## 责任范围

- 向 Agent 提供稳定能力桥和插件元工具。
- 加入复用优先、权限不扩大和保存关键结果的 Role 指引。
- 用受控资料处理任务完成生成、验证、修复、激活和使用闭环。

## 可独立分工的工作

1. 打通同 Session 动态发现与调用。
2. 完成一次授权资料处理的真实自扩展。
3. 验证修复失败插件和缺权限处理。

这些分工供 Leader 判断，不要求按步骤建立 WorkItem。紧密耦合的实现应由同一责任单元完成。

## 不在范围内

- 不强制创建 PluginDevelopmentTask。
- 不让 Leader 自动覆盖自身 Runtime 或全局核心能力。

## 完成证据

- 不改 Yui 源码、不重启 Controller，原 Task 使用新增工具取得结果。
- 验证错误可以由 Leader 修复后继续。
- 声明式验证与可执行验证分别说明，不能互相冒充。

验收场景：S28、S32、S33、S42、S45。场景定义见[统一验收说明](../../reference/acceptance-scenarios.md)。

## 实施入口

[详细技术方案](../designs/T10-self-extension.md)定义接口、改动位置的定位方法、存储影响、兼容路径和具体验证。共同执行约束见[实施路线](../README.md)。

Active Task 闭环不等待 T08；Draft 自扩展属于附加验证场景。
