# 验收场景

这些场景定义实现应满足的可观察行为，状态均为 **planned：待实施验证**。文档生成、链接检查和 TypeScript 编译不会把场景自动变成通过。

## 执行与证据

纯结构场景可用临时 Store、假 Endpoint 和受控外部服务执行；涉及真实 CLI、原生用户输入、实际权限与进程停止的场景，需要真实实现和明确授权环境。记录实际输入、结果引用、Provider 版本、外部效果证据和未覆盖范围。

通过一个 mock 拒绝不能证明宿主隔离有效；通过静态类型检查不能证明协议确认正确；界面显示 draining 不能证明进程停止。每个迁移 Task 应提交与其声称行为相称的证据。

## S01｜Draft 的 Leader 对话

**前提：** 存在未激活 Task，尚无常驻 Leader Session。

**操作：** 用户通过 Task 入口进入对话，并询问任务细节。

**预期：** 路由到该 Task 的 Leader，按需启动 planning 承载；不要求先建立 delivery 环境或先激活。

实施关联：T08。验证状态：planned。

## S02｜规划事实可接手

**前提：** Leader 已把目标、当前思路和重要决定写入 Task。

**操作：** 关闭原 Session，使用新的兼容 Agent 会话读取 Context。

**预期：** 新会话能读取已经确认的规划信息；不需要恢复旧终端或完整工具日志。

实施关联：T08。验证状态：planned。

## S03｜Role 配置与实际执行分开

**前提：** 一个 Worker 的 Turn 正使用 Agent A。

**操作：** Leader 将 Role 当前配置改为 Agent B。

**预期：** 当前 Turn 仍保留 A 的实际配置和结果来源；后续明确执行可以选择 B，WorkItem 身份不变。

实施关联：T03。验证状态：planned。

## S04｜直接完成无 Git 任务

**前提：** Task 只需产出一份文本说明，没有 Project 或 Git 资源。

**操作：** Leader 保存说明并提交完成。

**预期：** 允许 direct 完成，不强制建立 WorkItem、Review、branch 或 worktree；说明在重启后仍可读。

实施关联：T05。验证状态：planned。

## S05｜进度与结果独立

**前提：** 已存在被讨论或被接受的 Candidate。

**操作：** Leader 更新 Brief.currentFocus。

**预期：** 进度可见，Candidate 内容与验收不被自动改写或撤销；无需重新执行。

实施关联：T03。验证状态：planned。

## S06｜需求变化的显式判断

**前提：** 已有结果来源于较早的任务说明。

**操作：** Leader 修改要求，阅读原结果并明确接受其仍然适用。

**预期：** 接受可记录具体选择和说明，不以所有记录 revision 相等作为门禁；原 Candidate 内容不变。

实施关联：T03。验证状态：planned。

## S07｜Review 原始结果单份保存

**前提：** Reviewer 针对一个固定 Candidate 运行。

**操作：** Reviewer 返回包含建议、疑问或混合意见的文本。

**预期：** 原文只保存在 Reviewer Turn；Review 引用它，Core 不自动解析 verdict 或创建修复 WorkItem。

实施关联：T03。验证状态：planned。

## S08｜责任不因尝试失败消失

**前提：** WorkItem 仍为 open。

**操作：** 其 Worker Turn 因 CLI 错误结束。

**预期：** 错误和已有结果进入原 Turn，通知 Leader；WorkItem 仍可继续分配或由 Leader处理。

实施关联：T03。验证状态：planned。

## S09｜效果未知不自动重放

**前提：** 外部服务接受了请求，但 Yui 未收到最终回执。

**操作：** 连接断开或调用再次使用同一请求身份。

**预期：** 保留原操作和 unknown；不自动切 Provider／PTY 再执行，真实外部次数可核对。

实施关联：T01、T04。验证状态：planned。

## S10｜并发编辑不覆盖

**前提：** 两位受权调用者读到同一 Brief revision。

**操作：** 一方更新后，另一方提交过期写入。

**预期：** 后一写入获得当前版本和明确冲突，不覆盖前者；冲突仅影响该写入，不使历史结果无效。

实施关联：T01、T03。验证状态：planned。

## S11｜原生身份按证据保存

**前提：** 一个 Endpoint 只提供本地关联或传输写入，未返回 native Turn ID。

**操作：** Yui 建立 Turn 并显示执行状态。

**预期：** 本地 attempt 与 native ID 区分，缺失原生字段保持缺失，不伪造 native acceptance。

实施关联：T04、T07。验证状态：planned。

## S12｜长请求正常等待

**前提：** 协议请求持续连接且尚未返回终态。

**操作：** 超过一般短调用时间但没有明确失败证据。

**预期：** 仍表示 pending；不自动重试或认定 input 未接受，最终关联响应归原请求。

实施关联：T04、T07。验证状态：planned。

## S13｜结果版本明确

**前提：** Candidate 已引用文件的一版固定内容。

**操作：** 原工作文件随后被继续修改。

**预期：** 读取 Candidate 仍得到被提交的那版内容或明确外部版本；参考 URL 不冒充固定结果。

实施关联：T05。验证状态：planned。

## S14｜既有 Session 保持实现

**前提：** Session 已由实现 A 打开。

**操作：** 发布实现 B，并在该 Session 开始下一 Turn。

**预期：** 默认仍使用 A 和必要状态依赖，除非显式按可验证方式重建；不在每 Turn 强制升级。

实施关联：T04、T11。验证状态：planned。

## S15｜Context 核心一致读取

**前提：** Task 在持续写入消息和结果。

**操作：** 读取 Context 并分页获取 delta。

**预期：** 核心数据与 cursor 同一读视图，分页上界固定；外部观察另有时间和来源。

实施关联：T03、T06。验证状态：planned。

## S16｜读取不代表送达

**前提：** Message 尚未被目标 Agent 接受。

**操作：** 用户或 Agent 读取 Context。

**预期：** Message 不因此被标为已送达；投递接受依据实际执行证据。

实施关联：T03、T06。验证状态：planned。

## S17｜忙碌输入保留

**前提：** 目标 Role 的原生会话有活跃执行。

**操作：** 出现新消息或多次 Wake。

**预期：** 保留同一待投递输入并合并提醒，不创建竞争会话或丢消息。

实施关联：T04。验证状态：planned。

## S18｜局部故障交 Leader

**前提：** Worker 或 Reviewer 无法继续或主动求助。

**操作：** 故障被可信入口观察。

**预期：** 保存原事实并通知该 Task 当前 Leader，不自动升级成整个 Task 失败。

实施关联：T03、T04。验证状态：planned。

## S19｜Leader 故障交 Operator

**前提：** Leader 承载不可用，任务事实仍存在。

**操作：** 系统记录失败或 Leader 提出求助。

**预期：** 经已有消息路径通知 Operator，提供 Task 和执行引用，由 Operator决定具体操作。

实施关联：T03、T04、T06。验证状态：planned。

## S20｜Operator 由用户处理

**前提：** Operator 无法启动或其会话异常。

**操作：** 系统观察到该问题。

**预期：** 保留普通事实和待处理输入；不自动创建备用 Operator、恢复 Task、专门 watchdog 或救援 Agent。

实施关联：T01、T03、T06。验证状态：planned。

## S21｜迟到和重复结果关联

**前提：** 旧 Turn 已有终态，后继 Turn 正在执行。

**操作：** 旧执行终态重放或延迟到达。

**预期：** 只关联原 Turn，重复幂等；不完成或失败后继 Turn。

实施关联：T04。验证状态：planned。

## S22｜多路尝试关系

**前提：** 同一 Assignment 有两个副本，其中一个需要重试。

**操作：** Leader请求重试并选择结果综合。

**预期：** 重试仍属于原副本，综合明确选择来源；不把重试当独立第三意见，外部发布不默认复制。

实施关联：T04、T05。验证状态：planned。

## S23｜请求停止与实际停止分开

**前提：** 资源仍可能被子进程或原生后台活动写入。

**操作：** 发出取消或更换 Role 后准备冲突执行。

**预期：** 只凭取消请求或管理变更不能宣称资源停止；可查证、等待或换隔离资源，无关工作不被整体锁住。

实施关联：T04、T05。验证状态：planned。

## S24｜用户原生对话共存

**前提：** 用户直接在原生 UI 启动会话执行。

**操作：** Yui 同时准备提交输入。

**预期：** 按真实 busy／输入能力处理，保留请求；不争抢唯一对话所有权或悄悄混淆两轮结果。

实施关联：T04、T07。验证状态：planned。

## S25｜短工具实现切换

**前提：** 工具 A 已有进行中调用。

**操作：** 注册工具 B 并发起新独立调用。

**预期：** 已有调用仍用 A，新调用可用 B；A 在真实使用释放后才 dispose。

实施关联：T01、T02、T11。验证状态：planned。

## S26｜真实资源目标识别

**前提：** 同一个可写资源有两个展示别名。

**操作：** 两个操作分别使用不同别名尝试冲突写入。

**预期：** 资源能力识别真实目标并执行其必要条件，不只比较名称；不引入第二份资源真相。

实施关联：T05。验证状态：planned。

## S27｜空执行环境

**前提：** Task 不需要额外目录或资源准备。

**操作：** 执行 Activation。

**预期：** 空环境计划合法，Task 可以进入 active，不为了满足框架模型创建 worktree。

实施关联：T05、T08。验证状态：planned。

## S28｜Scope 不授予权限

**前提：** Task-local 插件声明访问一个尚未授权资源。

**操作：** Agent 尝试调用该能力。

**预期：** 缺授权返回明确事实；scope 和 manifest 本身不提供权限，Agent可请求 Operator／用户。

实施关联：T05、T09、T10。验证状态：planned。

## S29｜初始化只注册

**前提：** 候选插件初始化失败或试图先进行业务写入。

**操作：** 执行 activate。

**预期：** 不发布半套能力；初始化不允许借注册阶段完成业务副作用，当前可用 Provider 不受影响。

实施关联：T09。验证状态：planned。

## S30｜能力歧义和缺失可读

**前提：** 当前可见范围存在两个同名实现，或没有对应能力。

**操作：** Agent search／describe／call。

**预期：** 返回候选或 unavailable，显式选择后才调用；不按加载顺序覆盖，不阻止核心 Task 读取。

实施关联：T02、T06。验证状态：planned。

## S31｜验证与激活同一内容

**前提：** 插件 A 已通过验证。

**操作：** 源文件或打包依赖改成 B 后请求激活。

**预期：** 不能仅凭版本号复用 A 的报告，实际摘要与报告不符时需验证相应内容。

实施关联：T09。验证状态：planned。

## S32｜原 Task 实际自扩展

**前提：** Active Task 缺一个资料转换能力。

**操作：** 真实 Leader 编写、验证、Task-local 激活并使用插件。

**预期：** 不改 Yui 源码和重启 Controller，原任务获得可读取业务结果；仅加载成功不足以通过。

实施关联：T10。验证状态：planned。

## S33｜Agent 修复插件继续工作

**前提：** 自写插件的一项验证因输入边界失败。

**操作：** Leader读取报告、修改实现并重新验证。

**预期：** 在原 Task 继续，未通过内容不覆盖已可用实现；不由框架自动创建修复工作流。

实施关联：T10。验证状态：planned。

## S34｜效果与输出失败并存

**前提：** 外部动作已部分或全部发生。

**操作：** 插件输出不符合 schema 或后续处理抛错。

**预期：** 已得回执和部分结果仍保留，不能标为无效果并自动重跑整个动作。

实施关联：T01、T02、T09。验证状态：planned。

## S35｜新 Session 使用新实现

**前提：** 实现 A 的旧 Session 仍可用，B 已成功注册。

**操作：** 创建一个新 Session。

**预期：** 新 Session 默认采用 B，旧 Session 的实际配置不被改写；B 加载失败时原路径仍可用。

实施关联：T04、T07、T11。验证状态：planned。

## S36｜展示当前配置与实际来源

**前提：** Role 当前配置已变化，但旧执行仍存在。

**操作：** CLI 和 Web 显示当前任务。

**预期：** 清楚呈现当前配置与各 Turn 实际使用的配置，不把历史结果标签重写。

实施关联：T03、T06。验证状态：planned。

## S37｜历史成果独立读取

**前提：** 旧插件已无使用者，其可执行代码按保留策略释放。

**操作：** 用户读取历史 Candidate／Review／完成说明。

**预期：** 内容和必要来源仍可读，不要求重新启动旧插件；再次执行是新的能力请求。

实施关联：T05、T11。验证状态：planned。

## S38｜展示贡献可卸载

**前提：** 一个插件提供专用 CLI 命令或结果面板。

**操作：** 停用该展示贡献。

**预期：** 注册资源正确撤销，Task 与成果不删除，通用读取路径仍可用。

实施关联：T06。验证状态：planned。

## S39｜实现并存但事实单一

**前提：** 同一受支持版本中有当前和目标实现可选。

**操作：** 逐项切换新调用或创建新 Session。

**预期：** 一次工作只落一条路径，共用唯一 Store／Controller；效果未知不自动走另一实现。

实施关联：T00、T02、T04。验证状态：planned。

## S40｜当前 planning Turn 发起激活

**前提：** Leader 正在 Draft 对话中。

**操作：** 该 Turn 调用 Activation，随后结束；或用户在等待中取消。

**预期：** 请求立即返回引用而不自等待；结束后按当前有效意图采用；已取消请求不被继续执行。

实施关联：T08。验证状态：planned。

## S41｜管理交接保留工作

**前提：** Operator 为 Task 更换 Leader 承载，旧 Worker 仍在工作。

**操作：** 原 Worker 返回结果，旧 Leader 尝试新管理操作。

**预期：** 结果归原 Turn 并交当前 Leader；旧管理入口不继续越权；Worker 分配不自动重建。

实施关联：T03、T04。验证状态：planned。

## S42｜旧 Session 使用新增工具

**前提：** Agent Session 已通过稳定 Yui 桥运行。

**操作：** Task-local 激活一个新的短工具，并在后续桥调用中使用。

**预期：** 工具可发现和调用，不要求热改原生 schema 或升级 Endpoint；旧 Session 仍按原实现运行。

实施关联：T10、T11。验证状态：planned。

## S43｜结束与重开不重播历史

**前提：** Task 已结束，历史里有未决或已接受输入。

**操作：** 迟到结果到达，随后用户显式重开。

**预期：** 迟到结果只归档；重开不自动重新发送所有历史输入，负责人明确选择后续工作。

实施关联：T03、T04。验证状态：planned。

## S44｜存储采用有明确路径

**前提：** 隔离 Home 使用当前受支持存储版本。

**操作：** 执行需要 schema 变化的受控升级。

**预期：** 升级、备份和验证步骤明确；不假定旧 binary 能读取新 schema，也不以代码切路由冒充数据库回退。

实施关联：T00、T01。验证状态：planned。

## S45｜当前授权影响新副作用
