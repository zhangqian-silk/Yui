# Kernel：事实与执行边界

**层次位置：Minimal Kernel；为各层和 Plugin Fabric 提供共同基础。** 本模块拥有唯一存储与授权基础、操作事实机制和实例宿主。Plugin 模块使用该宿主管理贡献，不再建立第二套实例权威。

分层位置与完整工作关系见[总体架构](../architecture/01-overview.md)。

## 1. 定位

Kernel 为所有模块提供稳定基础，而不是实现任务业务。其范围是身份、存储事务、可信调用上下文、必要的外部操作记录，以及一个插件实例宿主。它不解释 Task 目标、Review 文本、领域资源或 Agent 的计划。

单用户单 Home 部署只需要一个实际写入协调者。进程锁、事务和当前 Controller 发现机制按现有实现复用，不引入分布式选主。

## 2. 公开端口

```text
Store.read / transact
Identity.allocate / validate
Authority.authenticate / authorize
Operations.begin / record / inspect
Host.attach / acquire / release / detach
```

这些名称是职责示意。存储端口不暴露给任意作者插件；具体应用模块通过受权能力处理 Task 修改。类型中的 actor 是可信入口得到的上下文，不是插件自己提交的 JSON。

## 3. 三类操作

| 类别 | 执行方式 | 持久化要求 |
|---|---|---|
| 只读查询 | 有界读取并返回 | 通常不建立 Command |
| 本地事实修改 | 事务、必要 revision 检查、来源记录 | 写入业务记录即可，不复制第二账本 |
| 跨进程／外部副作用 | 在发起前保存稳定请求引用，执行后保存处置 | 保留未知效果及外部回执 |

请求的幂等键由可信调用入口验证，去重范围至少包含调用主体、目标和具体能力。相同键携带不同输入不能被当作同一请求。重试一个读操作通常不同于重做一个邮件发送。

账本状态描述操作是否排队、执行或结束；效果证据描述已知没有效果、可能有效果或确认发生。执行失败不能推导效果为零。一个动作只完成部分时，保留已知子结果或原回执，不要求为此建立通用分布式事务平台。

## 4. 未知处置

当通信丢失而外部动作可能已发生时，保留操作引用和证据，返回 unknown。重复调用可以返回同一操作引用，但不能自动再次产生外部动作。

能查询外部状态时提供查询能力；不能查询时由 Leader／Operator 决定是否接受重复风险或采用其他方案。任何显式重做都应是可见的新决定和请求，不篡改旧记录来伪造未执行。

等待一个仍然连接正常的长操作属于 pending，不等于 unknown。最终准确关联的响应可以补齐已接受与结果信息。

## 5. 授权与身份

授权决定某个调用者能对哪个目标做什么。Task 模块定义角色关系，Kernel 验证可信上下文和目标范围。用户／Operator 的全局权限不由普通插件通过参数声明获得。

Role 实际承载更换时，旧承载的管理凭据应失效；它的原执行结果仍可通过可信采集路径写到原 Turn。历史回执写入与新的管理动作必须分开识别。

资源授权和配置快照也分开：保存过去用过的权限配置不代表未来仍有权限。受控外部动作在执行前检查当前授权；已经发生的外部效果无法靠撤销令牌消除。

## 6. 唯一实例宿主

Host 负责实例身份、生命周期和动态注册资源。插件模块负责选择包和构建贡献。二者共用同一个实例表述，不分别保存两套“当前活跃 Provider”权威。

注册的 listener、timer、route、进程连接和能力句柄都属于某个实例的 disposer。使用方 acquire 后得到稳定句柄，结束后 release。长期会话持有它实际使用的实现；短工具只持有到调用结束。

宿主不需要自己知道 Code Review 或 Git。其 drain 只意味着停止新的独立使用并等待已有引用结束，不是业务取消。

## 7. 存储及更新

业务模块在同一存储契约下定义自己的记录。Kernel 管理当前支持的 schema 和升级入口。普通打开存储不隐式执行复杂迁移；升级使用明确备份和采用步骤。

代码路由回退、数据库降级、恢复备份和撤销外部效果各有不同意义。文档和命令不能用同一个“rollback 成功”掩盖这些区别。

实现可以暂时有不同 Provider，但不能各维护一份 Task 状态或操作处置。系统不允许两个 Controller 各自认为自己拥有同一 Home 的执行权。

## 8. 失败责任与非职责

Kernel 记录可确定事实并返回可操作诊断。它可以完成事务重放、同目标查询和去重通知等机械动作，不自行安排业务重试、换模型或创建修复 WorkItem。

不建设 Operator 救援子系统。Operator 无法工作时，由用户使用普通操作入口和环境工具处理。

## 9. 验收要点

同一本地修改重复请求不产生重复记录；外部 unknown 不被自动重放；失败但有效果的记录可读；撤权不删除原结果；插件句柄 release 后 effects 被回收；读取不触发业务写入。对应场景为 S09、S10、S11、S12、S25、S34、S39。
