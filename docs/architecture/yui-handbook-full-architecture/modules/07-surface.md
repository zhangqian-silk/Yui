# Surface：一致的用户与 Agent 操作入口

**层次位置：Experience Plane。** 用户输入可以路由给 Intelligence Plane 中的 Operator／Leader，也可以直接调用 Capability Plane。展示消费 Context／查询；写入通过原子操作，不产生独立 Task 状态。

分层位置与完整工作关系见[总体架构](../architecture/01-overview.md)。

## 1. 职责

Surface 负责展示、采集输入、确认操作、调用能力和订阅更新。它不拥有 Task workflow，也不自己解释哪个结果应该被接受。

CLI、Web 和 Agent 工具对同一操作使用相同应用入口。CLI 的可读输出和 JSON 输出是同一结果的两种表示；不在 Web 里实现另一套重试或完成逻辑。

## 2. 两个对话目标

全局入口对应 Operator，Task 页面或 task enter 对应该 Task 的 Leader。Draft 页面同样有聊天入口。对话路由不以是否已经有常驻 Session 为前提，必要时由 Execution 按配置创建。

用户可直接执行明确操作，不经过模型。原生会话入口也允许继续与 Leader 交流；Yui 对无法观察的输入不声称拥有完整历史。

## 3. Task 视图

默认展示目标、当前要求、Leader 当前关注点、工作责任、结果与待回答问题。运行细节在可展开区域，包括实际 Agent、Session、Turn、错误和活动观察。

页面应让用户清楚区分：任务事实、当前配置和某次执行实际配置。Role 已改用新模型但旧 Turn 仍在运行时，显示两者而不是把历史执行标签重写成新模型。

不显示框架生成的强制下一步。可以提供当前对象支持的操作，但行动选择属于用户／Agent。

## 4. 读取与订阅

视图来自 Context 或受权查询。更新通知只触发重新读取或拉取 delta，不把通知正文当成另一份可写状态。网络断线后从游标补读或重建快照。

核心 cursor 不覆盖实时观察。页面显示观察时间和不可用来源，而不是用缺失值填充“正常”。可选插件面板失败不影响核心 Task 说明和结果读取。

## 5. 操作反馈

修改返回实际保存的记录或 operationRef。排队、等待、未知处置、失败和成功各有明确文案，不用一个“执行失败”掩盖可能已发生的效果。

确认用于扩大权限、破坏性动作或用户要求的决定，不为每一个已授权原子操作再加一轮固定人工审批。Operator 的自然语言操作同样遵守现有授权边界。

## 6. 插件贡献

CLI 可以注册命令描述并映射到能力调用；Web 优先接收受控面板描述、链接和结果呈现，而不是默认在前端执行任意插件脚本。

命令和面板随实例生命周期注册／撤销。卸载面板不删除 Task 数据，隐藏一个能力不等于撤销资源权限。可执行 UI 扩展若确有需要，需要独立明确的信任方式，不作为基础实现前提。

## 7. Agent 工具入口

Agent 使用稳定的 Yui CLI 或 capability describe/call 桥。工具目录可按 Task 当前可见范围查询；不必在每次 Prompt 中放入所有插件参数。

文档和命令帮助来自同一能力描述，尽量避免手工维护两套目录。工具输出包含稳定引用和简明事实，长内容提供读取指针。

## 8. 故障呈现

Worker／Reviewer 问题在 Task 中可见；Leader 问题按既有消息路径进入 Operator；Operator 的问题由用户处理。Surface 提供普通查询和操作，不附带独立自动修复逻辑。

插件、Endpoint 不可用也应允许显示已有结果。用户不需要启动生成该结果的旧 Runtime 才能打开文件或阅读完成说明。

## 9. 验收要点

CLI/Web 同源、Draft 聊天路由、配置与有效执行显示、断线补读、插件视图卸载、未知效果文案和无隐藏恢复流程。对应场景为 S01、S15、S16、S17、S19、S20、S30、S36、S38。
