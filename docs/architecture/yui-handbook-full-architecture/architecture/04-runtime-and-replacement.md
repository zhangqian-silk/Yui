# 执行、连接与实现替换

**层次位置：Execution Plane；通过 Capability Plane 提供执行管理入口，并由 Plugin Fabric 支持实现替换。** 角色行为属于决策层，模型及工具的实际运行发生在本层。

## 1. Execution 的外部模型

Agent 选择某个 Role 执行明确的工作，Yui 创建相应 Turn 并负责把输入交给配置的 Agent。上层获得执行引用、必要状态和结果，不必理解通信协议。

Turn 记录一次执行的目标、输入、Role、实际配置、关联身份、结果与错误。Session 是可复用的会话；Host 是持有连接或进程的实现。Task 不是其中任一对象的子生命周期。

Execution 只执行已经提出的请求。它可以因为同一 Role 正忙或资源容量不足暂缓启动，但不自己选择别的 Worker、模型或方案。

## 2. AgentEndpoint

统一入口保持少而明确：

```text
open / resume
submit
inspect
cancel
steer（可选）
events
detach
```

`detach` 只结束 Yui 自己的连接或附件，不默认取消远端执行或销毁原生会话。取消和停止是显式操作，区分已经请求停止与确认停止。

能力描述只表达系统确实需要区别处理的事项：能否恢复原会话、能否可靠关联输入、是否支持运行中 steer、能否取消、是否可提供终端。未知能力明确未知，不根据 Agent 名称猜测。

## 3. Runtime、Protocol、Transport

```text
Role 当前配置 / Agent 选择
             |
        AgentEndpoint
             |
   +---------+------------------------------------+
   | 产品适配       协议适配           通信载体     |
   | Codex          App Server         支持的连接   |
   | Claude Code    stream-json        stdio        |
   | 其他 CLI       ACP                支持的传输   |
   | 终端型 CLI     terminal           PTY          |
   +----------------------------------------------+
             |
    原生 Session / Turn / 结果
             |
    必要执行证据写入持久化记录
```

表中的连接组合由具体产品适配验证并声明。上层看到 AgentEndpoint，不需要配置或保存一棵协议图。

| 职责 | 内容 | 示例性实现 |
|---|---|---|
| 产品适配 | 找到 CLI、读取版本和配置、选择启动方式 | Codex、Claude 或其他 CLI 适配 |
| 协议适配 | Session／Turn 交互、错误和事件解释 | App Server、流式 JSON、ACP、终端模式 |
| 通信载体 | 启动连接并收发数据，管理本地句柄 | stdio、PTY、WebSocket、已有代理连接 |

这些是接口边界，不是任意组合的笛卡尔积。产品适配声明经过验证的连接配置；Endpoint 工厂解析所需依赖并建立实例。Codex 可使用其 native 协议适配，支持 ACP 的其他 CLI 可以复用 ACP 适配。协议版本和能力在实现时以实际协商为准。

Native 产品与专用协议可以放在同一个包里。通用协议或载体只有出现独立复用需求时才单独作为插件。Task 配置通常只选择 Agent 或连接预设，不保存复杂的协议绑定图。

## 4. 提交与返回

一次输入可能得到：明确接受、仍在等待、明确未产生效果、结果未知。通信写入成功不是对所有协议都等价的接受确认；晚到的、可准确关联的最终响应也可以提供接受和完成证据。

正常等待不能被统一超时策略判成业务失败。连接丢失之后，如果无法确认输入是否执行，保留原尝试身份并读取可得证据，不自动切换另一个实现重发。

PTY 提供人工可用的终端入口，但不因此自动具备结构化执行确认。不能把终端空闲图案当作某个 managed Turn 已完成的证明。

## 5. 多路与后台执行

多路执行共享一份明确 Assignment，记录副本与重试关联即可。Leader 决定参考哪些结果以及是否综合，不设置框架统一的成功数、投票或降级规则。

多路写入需要分离工作环境或由资源能力明确支持并行。支付、发送、发布等外部动作不因 replicas 参数被自动复制。原生 subagent 可以辅助当前执行，但不会自动进入 Yui WorkItem 图。

父 Turn 结束不一定代表所有后台活动都已经停止。只有需要继续使用可能冲突的资源时，才查看相关活动证据或采取停止／隔离操作；不把不相关的后台诊断变成整个 Task 的门禁。

## 6. 哪些可以热更新

| 对象 | 生效边界 | 保持不变的内容 |
|---|---|---|
| CLI／Web 无状态展示贡献 | 注册切换后新读取 | 已保存任务事实 |
| 能力目录 | 新查询立即看到 | 进行中调用选择的实现 |
| Skill／Role 模板数据 | 后续应用或执行 | 历史配置快照和输出 |
| Role 当前配置 | 下一次兼容执行或新会话 | 已运行 Turn 的实际配置 |
| 短工具实现 | 当前调用结束后或新独立调用 | 当前调用及其回执 |
| 长期 Endpoint 与协议实现 | 默认以新 Session 为边界 | 已有 Session 与必要有状态依赖 |
| 核心存储和授权契约 | 受控软件更新 | 数据意义、权限和操作事实 |

这里的“热”只表示不必重启整个 Yui，不代表所有正在运行的对象必须即时采用新代码。

## 7. generation 的最小意义

generation 是实现实例的身份，用于说明某次调用实际落到哪份代码和配置。普通 Agent 不必手动管理它。宿主在选择实现时取得句柄，直到调用或 Session 不再使用后才释放。

新 Session 默认选择当前实现；同一旧 Session 的下一 Turn 通常继续原实现。需要换实现时，Leader 可以关闭或停用旧会话再创建新会话。通用透明状态迁移不是必要能力。

只需要固定会话实际持有的状态型依赖；无状态目录查询不必把整个系统依赖树冻结下来。动态注册的新工具可以经稳定的 Yui 调用入口在同一 Session 后续使用，而无需重载原生工具列表。

## 8. 插件启停

启用新实例时先完成验证与注册准备，然后一次发布完整能力集合。注册初始化不执行业务副作用。准备失败不影响当前可用实现。

普通停用阻止新的独立使用，既有调用或会话根据原句柄结束。权限撤回则立即影响新的受控副作用，两者不是同一个操作。无法撤回已经到达外部系统的动作时，记录实际情况，不宣称“卸载插件已经撤销操作”。

当没有实际使用者时，旧实例和代码可以释放。历史结果与来源元数据继续保留。存储迁移和不可兼容的内核更新走正常更新流程，不使用插件 drain 冒充数据库迁移。

## 9. 失败处理

Endpoint 如实提供证据。Worker／Reviewer 的失败由 Leader 处理；Leader 的失败由 Operator 处理；Operator 由用户处理。常规连接维护可以重连相同目标，但不自行改变任务策略。
